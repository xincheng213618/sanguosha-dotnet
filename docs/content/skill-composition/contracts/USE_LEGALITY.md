## Target eligibility and action restrictions

- Virtual Slash target eligibility uses `CoreNativeTargetLegalityRuntime.CanUseVirtualSlashTarget`; complete candidate sets use `GetVirtualSlashTargetSeats` over the same private decision. Preserve candidate order and repeated occurrences. Each candidate retains alive/self and source-target qualification before the first eligible candidate samples target-independent material and final-appearance admission once for that call. Quota, distance and target restrictions still run per target; this local result is neither a cross-query cache nor payment permission. Callers do not repeat common SelfOnly, directed, effective-kind target bans or beneficiary-suit shields. Preserve source, material, distance, quota and rule-specific target requirements, including extra candidate gates. Known suitless uses pass `Suit.None`; unknown suits remain null. Keep actual sequential effects, supplied responses, varying actors and accepted-use continuations on their real sampling boundaries.

- Applied card-action restrictions use the shared prohibition store and AppliedCardActionRestrictionsRuntime with declared recipients, material facts and lifetimes. Actual-use expiry consumes shared native declaration and self-response facts independently of source survival; do not rebuild character grant/consume ledgers or treat payment, ordinary play or supplied responses as another actual use.

- An optional use of a gifted equipment card binds the named choice to the original public card set and its recipient. Display, submission and native use read the same equipment eligibility, including current hand ownership, slot availability and use restrictions. The choice supplies the timing for the authorized use.

## Native Slash requests

- Issued native Slash requests use `INativeProgramSlashRequests` on the original `ProgramSkillFrame.SlashRequest`. Keep the issued opportunity, selected target, accepted payment attempt and actual `CardUseFrame.ProgramSlashRequestExecution` distinct. Loop issuance uses the real original cursor; retries get a new attempt ordinal. Material selectors and unpaid slot choices do not accept a use. Preserve the original private decision explicitly through paid children; do not fabricate a Play prompt or borrow an unrelated active request.

- Slash-request offer permissions and accepted-use permissions declare source loss and owner death independently. `OwnsAcceptance` is a fact read, not permission to create another use. The first actual execution checks its declared permissions, then retains its original accepted actor and target independently of legitimate native role or target changes. Source business reads the exact original parent and the real native action, provider and materials; shared request queries never reconstruct character Prepare or issuance histories.

- Requested Slash rights use the shared permission matcher. Keep prospective distance separate from physical-Slash-only issued distance, request targets separate from broader declared quota audiences, and candidate Slash quota separate from actual debit exemptions. Generic Play suppliers retain the exact accepted request's base count flag; the Play transport does not turn a forced use into ordinary quota consumption, while an independent producer keeps its own explicit count contract. A genuine paid producer that returns without a use records one typed request failure, never a fake CardUse or declaration. The default failure policy cancels the binding; explicit `ResumeOriginalInstruction` returns through the declared ChoiceResult/FixedTarget protocol or the source's actual business owner. Consume a failure once before releasing its attempt for a permitted retry, and keep original costs paid.

- `CoreGameEngineAssistedPhysicalCardsRuntime` still initializes fixed-target requests through 移动姜维 and 复掠. Once issued, `GetOffer` answers continuing eligibility.
