# 基础能力：方法与地图

## 装备生成与移动窗口

蒲元本体只声明 JSON。`offerGeneratedEquipment` 声明牌面模板和来源，随机私有候选保留在原帧；`selectRandomPileEquipment` 只读取实际牌堆／弃牌堆；`placeBoundEquipment` 复用原生装备替换、授技、移动子窗及原帧返回。既有 `chooseOption` 可携带整数，由只读 `choiceNumber` 表达式供普通节点读取，不添加锻造品质专属指令。

实体来源放在 `Card.EquipmentOrigin`，寿命由 `EquipmentDestinationPolicy` 一个位置解释。`GeneratedEquipmentRuntime` 在实际弃牌记录上执行入弃牌堆销毁；共享 `equipment.destroyedThisTurn` 读原移动记录与批次号，给原产生技能回答本回合销毁批次数，不新增蒲元计数器或私有证明事件。装备移动开始时捕获有效的 `ownEquipmentOnly` 离区候选；原窗口签发 `ProgramInvocationAuthorization`，延续该次离区效果，不更改持有或有效性答案。

等价消费者全部走已有共享装备来源／目的地策略；无双商店的离装备区销毁与神工的入弃牌堆销毁是不同寿命。旧随机空栏放置、实际使用装备与本次从牌堆随机取得后直接置入的规则不同，保持各自的资格与使用流程；本批不宣称“装备”大类已完整迁移。新能力没有武将分支；天机图复用共同离区窗口，镔铁双戟扩展已有原生用牌实体回收至杀被抵消窗口，未复制回收账本。

规则来源与用户指定的手动锻造选择见 [蒲元来源](../sources/ol-pu-yuan-2026-11-01.md)。

属性杀转换使用同一个声明身份与后续转换生产者，普通视为杀、属性杀和装备／武将牌堆材料均经同一目标与次数查询；同一授技实例不能通过不同别名重复转换。五行鹤翎扇不添加装备专属转换分支。移动记录冻结 `PrintedSuit`，弃牌花色统计与红色弃牌回收都读取原记录，销毁后不再从目的地区域反查实体；旧记录仍可回退读取实体牌面。

`selectTargets.allTargets` 在原帧直接选择当前用牌的完整目标集合，供同一批目标的强制效果使用；乌铁锁链因此无需新增“横置杀目标”复合指令，也不让玩家把强制效果缩小为单人。

技能应当是规则概念的组合。前半部分是发现、判断和补齐基础能力的方法，后半部分是当前地图，由执行者在每次补齐后更新。

## 干净的架构是什么样

判断架构是否干净，靠读代码回答下面这些问题，而不是看行数或指令数：

- **一个概念，一个归属**：每个规则概念（技能有效性、使用合法性、获得、交给、距离……）只有一个拥有者。“这个技能现在有效吗”“这张牌能用吗”这类问题，在引擎中只有一个地方回答。
- **依赖方向单一**：规则概念不知道具体武将；武将依赖概念，武将之间互不调用。共享查询里没有人物分支。
- **层次分明**：每条规则落在它该在的层——触发时机、效果步骤、持续规则（修正 / 查询）、流程（顺序、分支、逐个结算）。“此次伤害 +1”是修正，不是伤害步骤；“不能使用”是查询，不是执行动作。
- **技能读起来像规则原文**：对照一个技能的描述，可以在它的 JSON 中逐句找到对应的部分，没有为了凑合实现而多出来的步骤，也没有藏在 C# 里的半句规则。
- **改动是局部的**：改一个概念时不用碰技能；加一个技能时不用碰引擎或其他技能；新老技能的交互由概念保证，而不是靠彼此打补丁。
- **只有一条路径**：同一件事没有新旧两套实现并存，也没有为过渡留下的适配层。
- **信任边界清楚**：校验只放在边界（命令输入、加载、存档恢复、执行器），内部代码互相信任，不重复自证。

从“使用/响应合法性”批次起，完成还必须通过依赖方向验收：对应共享模块不再依赖具体人物，人物实现只依赖共享能力。Entries 和 DeferredRuntime 解包后仍按实际目标记依赖；把调用隐藏到上下文、服务定位器、通用查询接口或另一个人物包装器中不算消除。现有机制检查的存量基线只约束不新增及及时收缩，不能拿基线通过替代这项完成标准。反向依赖基本消失后，再把剩余注入按真实概念收成能力接口，不单独追求构造参数变短。

看代码增长落在哪里：概念层（共享能力、查询、层次之间的接口）的代码随概念增加而增加，补齐后趋于稳定，这是健康的；随武将数量线性增长的专属代码、适配层、转发和自证，是不健康的。正常迭代中，前者可以放心增加，后者应当趋近于零。

行数和指令数只是表现，不是目标。多数情况下，架构变干净后体积会变小；但如果增加代码能让结构更干净，例如补一个完整的概念、明确一个回答点、拆开一个焊在一起的指令，就应该增加。

## 发现缺口的信号

在日常开发中遇到下面任一情况，就说明有基础能力缺失，应停下来对照本文，而不是绕过去：

- 准备新增的指令名里含有武将名、技能名，或含 Then / And / Or / If / When。
- 同一个规则术语已经有两个以上专属指令或专属实现。
- 一个共享查询里出现了针对某个人物的分支。
- 回答同一个“能不能 / 是不是”的问题，需要查看多个地方。
- 为了让新技能和老技能正确交互，需要修改老技能的代码。
- 写 JSON 时必须借助一个只服务本技能的 C# 指令，否则无法表达。

## 判断：封装、组合还是保留

- **封装成基础能力**：规则里有术语的概念（失效、获得、交给、视为、限制使用、觉醒……）；引擎需要在一处回答的问题；会与其他技能交互的状态。即使目前只有一个武将使用，也应封装。
- **用组合表达**：“先 A 再 B”、按结果分支、按条件执行，用 JSON 步骤序列和 `expression` 条件表达。即使很多武将都这样写，也不封装成新指令。
- **保留 C#**：单个武将独有、与其他规则没有交互的特殊流程。不为了消除它而去造一个只有它会用的“通用”能力。

使用次数只用来发现问题（同一概念出现多种写法），不作为是否封装的依据。

## 补齐一个概念的步骤

1. **普查**：在 JSON 和 C# 中找出这个概念的全部用法，整理出它在规则上的维度（动作、对象、范围、持续、例外），以及它与其他概念的交互（例如锁定技不受失效影响）。
2. **定义**：确定最小的参数集合、唯一的回答点，以及它分别落在哪一层：效果步骤、持续规则（modifier / 查询）还是触发窗口。参照已有的同类能力，复用现有存储和协议，不另建体系。
3. **实现并迁移**：在同一批中实现能力，并迁移所有能等价表达的消费者；删除旧的专属指令、分散判断和人物分支，不留两套实现。有规则差异的保留原实现，在本文记一行原因。
4. **锁定**：在 AGENTS.md 中用一句话写明“该概念统一使用这个能力”，并更新本文地图中的状态。
5. **自检**：完成前用“干净的架构是什么样”逐条检查这个概念：
   - 一个用到它的新武将，能否不写 C#？
   - 引擎中是否还有第二个地方在回答同一个问题？
   - 迁移后的技能是否能与规则原文逐句对应？
   - 是否还残留旧路径、适配层或人物分支？

   任何一条不满足，就继续完善，或者在本文说明原因。

## 选择下一个概念

优先处理离“干净”最远、交互面最大的概念：同一概念的写法越多，被其他规则查询得越频繁，就越优先。每完成一个概念后重新评估顺序。日常新增武将时发现的缺口，记入地图，按同样的标准排队。

用户已授权后续按最佳设计推进，不再逐项确认常规方案、JSON 迁移和已查明的行为修正。重要规则取舍及兼容性影响仍须写清楚；旧局无法恢复时沿已有规则开新局，保留源存档。不得据此自动扩大验证为全量或发布。

## 缺失项的证据

- **技能状态**：初始普查发现共享查询直接调用刻铭、各失效判断分散；现有负状态与刻铭调用授权已迁共享边界，旧 CurrentTurn 资格谓词已删除。主公投影、私库、HP、装备花色、落雁与官渡等正向来源关系尚需继续收口，整体仍未完成。
- **使用合法性**：新虚拟杀的共同目标限制已由 `CanUseVirtualSlashTarget` 回答，迁移结果见末节。实体杀、已受理用牌及非杀入口仍有 `IsSlashProhibited`、`IsCardTargetProhibited`、`IsBlackTrickTargetProhibited` 等不同组合，整体未完成。
- **获得 / 交给**：例如 `obtainOneFromEachSelectedTarget`、`revealHandColorDiscardAndTake`、`giveAllHandAndStartRecipientPindian`、`revealHandGiftAndResolveRecipientChoice`，大多是“获得 / 交给 + 其他步骤”的组合。
- **觉醒 / 限定技**：如 `awakenOlTianxing`、`awakenJianghuo`、`awakenHappyTaishiCiPowei`。每个觉醒技都单独写了检查、标记和后续变化。

## 当前建议顺序

基于本次盘点，按缺口大小和交互面排序，执行者可在普查后调整：

1. **技能状态**：一个动作（失效 / 失去 / 夺取 × 对象 × 范围 × 持续），一个持续规则（条件期间失效），一个“技能是否有效”查询；移除 `HasRuntimeSkill` 中的人物分支。
2. **使用与响应合法性**：一个“能否使用 / 能否指定 / 能否响应”查询，由 modifier 声明限制；现有 `grantTurn*Prohibition` 改为写入同一来源。
3. **获得 / 交给**：统一来源区域、选择者、可见性和数量，拆掉“获得 + X”的组合指令。
4. **觉醒 / 限定技**：统一的觉醒条件（表达式）、已发动状态和后续技能变化（复用技能变更）。
5. **无效 / 取消目标**、**装备**、**弃置参数化**、**伤害修正**。

## 技能状态：普通限制与归属

### 归属与维度

- 存储复用来源明确的 `CharacterSkillSet`；限制与获得来源一同随 revision 失效缓存，不新增 pending 或独立状态机。
- `SkillAvailability` 区分 **持有** 与 **有效**；`MatchSkillBindingIndex` 缓存回答并构建绑定。调用是否允许仍由实际触发窗口、次数、支付和目标资格回答，不能用持有代替。
- `skillState` 的动作是 `suppress`（仍持有但失效）、`lose`（失去当前来源）、`transfer`（借出方失效、施术方获得独立来源）。后者不表示永久夺走；实际失去并获得应分别表达两个动作。
- 范围为 `all / nonLocked / named / chosenFromTarget / expression`，可限定 `printedOnly`、`excludeLocked`；`characterOnly` 默认 true，显式 false 才覆盖装备来源，模式规则始终保护。
- 期限为本回合、本轮、指定角色最近一次回合结束、永久。`untilTurnEndOf` 默认包含当前回合；`afterCurrentTurn:true` 才排除发出时的回合。`expireOnDeath:true` 另以受影响目标（借出方）死亡为结束条件，不与回合结束座位混用。
- 失效覆盖匹配的现在和未来来源；暂时失去只限制当时的 grant，结束时移除限制，不能恢复永久失去的 grant 或删除后来独立获得的来源。永久失去直接禁用当前来源，不保留将来一切同名技能都失去的通配限制。
- 借用复用已持有的实例、boolean 状态和次数，不重复发获得事件；到期只移除本来源。
- 本回合期限沿用实际回合清理位置，在归还扣押牌可能打开移动子结算之前解除。指定角色回合末/死亡期限走各自事件边界；不能只因期限名字相同就改变 BeforeEvent/AfterEvent 顺序。
- 技能筛选复用 expression；`number` 的 `skill.locked / limited / awakening / lord / printed / ordinal` 是本次候选技能的内建事实。普通 number 和牌绑定仍走原资源检查；筛选结果在本步确定，不成为持续条件光环。
- 选择挂在原帧，按 chooser 的 `CreateSnapshot` 限制候选并使用私有 prompt；服务器仍校验回答，续接执行原指令后面的普通步骤。冷恢复继续接受命令重放，不增加存档版本门槛。

### 限制混入真实授予的实证

直接遍历 `SkillGrants.Grants` 并不自动表示资格漏洞；必须区分持有、有效性、来源和恢复职责，不能靠统一补 `IsEnabled` 修复。

| 已核实路径 | 当前具体风险 |
| --- | --- |
| OwnedAndRestorableRoundSkillGrants → GrantDamageTargetSkillAndDrawByRound | 假限制被当 ExistingGrant，跳过真实授予并冻结假身份 |
| 夏侯恩失去/恢复完整 grant | 把限制当技能保存；到期后又恢复旧限制 |
| 鲍三娘整体换技 | 整表 RemoveGrant 会一并删无关限制 |
| 卑弥呼/谋曹爽/王允等按名撤技 | 假项被删除或进入撤销事实 |
| 无双 native facts | 整表冻结把假授予送过模式的授予事实边界 |

真实 live grant 字典只有 `CharacterSkillSet._grants` 一处。限制表归同一个角色技能集合对象，不能放按 seat 的旁路；Transfer 的正向获得是真 grant，临时失去/可恢复的 disabled 真 grant 也仍是真 grant。模式换人复用/替换该对象的既有生命周期要保留。

有效性缓存必须感知限制变化；持有变更观察只反映真实授予集合变化，不能继续产生伪 SkillsChanged。

### 三处匹配的重复与缺陷

Issue、Candidates、Matches 重复 Mode/人物来源/印刷来源/Locked。Filter 目前只在候选端执行，随后按 SkillId 去重，Issue 再捞全部同名 grant：`skill.printed` 过滤掉的 acquired 来源可能被捞回。必须保留真实 GrantId/SkillInstanceId/SourceId，不在展示去重时丢掉规则范围。

统一纯数据匹配函数只接 selector、真实 grant、定义和只读来源上下文。Mode 保护无条件；可见性只在选择外层处理，不进入有效性或 while。NonLocked、ExcludeLocked 归一为同一种过滤表达式；不能在三处各保留分支。

### 持续条件与调用授权边界

复用现表达式的 HP、数量、存活、翻面/横置、参与者集合和技能元数据。缺少的角色/阵营、标记手牌、有效花色、phase/dying/prelude、来源关系按真实消费者补共享原始读取，不先建大全。

`handLimit` 会回查技能数值贡献，Owned/Effective 也回到 shard，不能在 while 中这样递归。while 必须来自原始事实；确需“有效源”时由同一求值器按明确依赖计算，不能偷换成 raw enabled。while false 不等于删限制，条件再次成立应重新生效。持续规则没有原帧时不能保存或查找已结束 ProgramSkillFrame；帧内普通 number/card 绑定不擅自变成持久上下文。

第一版对有 while 的状态实时求值/重建；不能只按命令 Revision 缓存，因为同一个命令的子帧也会改变事实。

刻铭复用原 DamageTriggerWindow 当前 candidate 上的窗口/binding/instance/hash/occurrence 授权，在 ProgramTriggerRuntime 准入、ProgramBindingRuntime 开始、原 ProgramSkillFrame 执行及支付子回程认可本次调用。删除 NationalSkills 的三条 fallback；不生成 grant、不把授权塞进 Owned/Effective。

### 统一期限结构与格式边界（已确认实施）

内部期限归一为一组结束边界，任一命中即结束；永久状态是空集合。每条边界含事件、主体、事件前/后、发出时的 occurrence 锚点及是否跳过该次，不再由 Duration/EndSeat/AfterCurrentTurn/ExpireOnDeath 的组合各写一份分支。

边界包括原生回合清理、实际 TurnStarted/TurnEnded、轮号推进、实际阶段开始/结束及死亡。原生回合清理与 TurnEnded 之前不是同一位置，不能合并到一个模糊的 before；轮号推进不依赖可选 RoundEnded。阶段期限以真实 phase occurrence 为锚，不把准备/结束阶段等同回合。

本批采用的新 JSON 形状：

```json
{"op":"skillState","action":"suppress","target":"selectedTarget",
 "match":{"filter":["==",["number","skill.locked"],0]},
 "until":[
   {"event":"turnStarted","participant":{"kind":"target"},"timing":"before","skipIssued":true},
   {"event":"death","participant":{"kind":"target"},"timing":"after"}
 ]}
```

持续条件另以 `while` 接现有 expression，限制表保存声明和已解析主体，不保存帧或人物判断委托。事件主体 `owner` 是发出者，`target` 是受影响者，`turnOwner` 是发出时的实际回合者。`match.filter` 中的帧绑定仅用于签发时筛选，随后冻结真实 GrantId；只读技能元数据的过滤保留为声明，才能覆盖以后新获得的同名来源。第一版持续条件支持失效/失去，不接受尚未定义借入正来源条件语义的 `transfer + while`。

**只保留新写法**：全部相关人物 JSON 和内嵌程序统一使用新结构，旧字段解析已删除，不加兼容别名和旧指纹保留层。旧存档可以因内容指纹变化无法重放；按既有桌面恢复规则初始化新局，不能立即覆盖原文件。不另加玩法 epoch 或 checkpoint RulesVersion。

已核实 `Replay.cs:30` 与 `Session/CommandSession.cs`：checkpoint 是配置、内容签名及接受命令前缀；Restore 重放命令，没有直接序列化 live SkillGrant/限制表，故内部负限制分表本身不需要修改存档记录或版本。回放恢复、命令失败后的可信前缀、事件集合冻结仍须验证。

### 统一结构与实际阶段限制

- 期限只执行 `SkillStateLifetime.Until` 的边界集合；旧 Scope/Duration/EndTiming/Lease 模型和 JSON 字段解析删除。回合清理的前后、TurnStarted/TurnEnded 的前后、实际阶段及死亡均接原边界；轮号推进仍独立于可选 RoundEnded。同步规则事实栈只提供发出时的 occurrence，不记录另一份历史或 pending。
- `CharacterSkillSet.Restrictions` 保存负状态；`Grants` 只保存真实来源。有效性缓存用综合 `Revision`，真实技能变更观察用 `GrantRevision`。可恢复的 disabled 真技能仍保留在技能表，没有用过滤 IsEnabled 掩盖混表问题。
- 签发、选择及有效性统一调用 `SkillStateMatcher`。选择界面按名字合并展示，但每个选项保留真实 GrantId；`skill.printed` 不再误伤同名 acquired 来源。只有瞬时帧绑定筛选需要冻结，持续元数据条件仍是数据。
- 周年/欢乐神钟会砺誓的第一项在原实际阶段应用处签发 NonLocked，至该种实际阶段结束；`while: ["inIssuedPhase", "target"]` 比较完整的发出阶段 key。插入子阶段时暂停，恢复原 key 后继续生效。删除 `IsLishiPhaseSuppressed`、对应转发及专属 revision 更新，其余四项惩罚和规则所需的已应用记录保留。
- 原生回合清理的 after 即该清理方法完成之后、返回暂存牌之前；即使没有普通用牌效果过期，也会经过这个边界。此机制位置保留在本地图，不进入 AGENTS。

截至统一期限这一批，技能有效性整体仍是**部分完成**：上述两版砺誓和雅士已退出旧资格链；封冻、阴鸷、完杀、昀政、借入来源以及外层来源资格/刻铭调用授权列为后续。没有用注册表、接口列表或新资格回调替代它们。共享条件世界只读原始参与者、牌区和实际阶段，不查询技能有效性或手牌上限。下一批进展见下文。

恢复失败分支仍停止自动保存、初始化新局并保留原文件；内部状态重构不改变这一保存与恢复边界。

### 持续状态声明：用户确认的语义

封冻、界完杀与韵筝应由同一 availability 求值器根据持续声明和原始事实回答；不能在 while 内回调 HasRuntimeSkill/GetShard/HasCardPolicy。需要的事实分别是当前实际回合/进行状态、当前濒死者、手中实体标记数量。桃的使用限制、韵筝手牌上限豁免及原始标记记录仍是各自规则消费者，不能随技能有效性旧方法一起删除。

用户已确认在 rules program 增加 `skillStates` 声明段，每项复用 action、match 和 while，加目标范围；例如缠怨：

```json
{"skillStates":[{"action":"suppress","target":"owner",
 "match":{"filter":["and",["==",["number","skill.character"],1],["==",["number","skill.isSource"],0]]},
 "while":["==",["hp","owner"],1]}]}
```

**施加与生效分开。** 原技能只负责施加，已施加状态独立保存到受体的 Restrictions；施加者死亡、原技能消失或失效都不自动撤销。后续只看受体条件、声明的期限与解除规则。不能每次从当前有效来源重算状态，更不能让化身库与普通路径各定义一套缠怨。

共享授予边界在真正取得声明时一次物化状态；绑定补初始来源，Grant、首次 enabled、选将/明置准入复用同一数据应用方法。查询只读现有表，不凭历史补状态。永久定义用真实 grant 身份和声明序号标识，不制造程序帧 origin；后续 disable/remove 原 grant 不删除状态。原生有帧状态保留原来源和游标契约。

- 两版缠怨是同一种状态，结构等价的已施加声明形成来源集合，`skill.isSource` 同时豁免二者。集合来自已存状态，不看原 grant 是否仍有效，也不列人物 ID。
- HP 始终是局内的统一体力。持续条件复用既有 `HealthQueries.UnambiguousHp`，它读取模式转换后的 CharacterState 并尊重原生已选体力池；删除持续条件另写的“双池不等直接 unknown”分支。没有新增状态专属体力口径。
- `cannotChallengeDeclarations` 等已施加状态的附带效果从同一声明定义读取，不能随原 grant 消失而丢掉；不把它伪装回真实持有的技能。

这项独立状态原则不把正向主公/私库/HP/装备来源关系改成永久获得；它们仍是“是否持有这个来源”的另一概念，按前面的来源数据审计继续收口。

### 按事件施加的限制（已确认并落地）

永久附着的缠怨与“每次窗口接受一次”的封冻/界完杀不是同一种施加时机。后两者不能在取得源技能时挂一个永久 while，否则临时源技能移除后，未来回合仍会重新生效；也不能塞进现有普通 trigger 窗口，因为那些窗口晚于部分资格查询。现有 `selectedTargets` 还没有在 skillState handler 中批量签发，不能把枚举存在当作已实现能力。

用户已确认扩充现有 `skillStates` 声明，不加解释器或人物回调：可选 `on` 复用期限的事件、主体和前/后结构；可选 `when` 是本次施加的表达式资格；`while` 只控制已施加状态何时生效；`until` 仍复用现有结束边界。没有 on 的已接受写法继续表示在真实取得声明时施加，不引入旧 suppressionRule 别名。

```json
{"skillStates":[{
  "on":{"event":"turnStarted","participant":{"kind":"owner"},"timing":"before"},
  "action":"suppress","target":"all",
  "match":{"filter":["==",["number","skill.locked"],0]},
  "while":["and",["not",["same","owner","target"]],["inIssuedTurn","owner"]],
  "until":[{"event":"turnEnded","participant":{"kind":"owner"},"timing":"after"}]
}]}
```

界完杀采用 `on: {"event":"dyingStarted","timing":"before"}`，`when: ["isTurnOwner","owner"]`；本次原生濒死身份和受害者冻结在已施加上下文，`while` 用 `inIssuedDying` 暂停挂起的外层窗口，并豁免施加者和该次受害者。`until: [{"event":"dyingEnded","timing":"after"}]` 接现有 `DyingResolvedEvent`，精确结束签发时的原生窗口，覆盖救回和死亡；不按“后来任一濒死结束”解除。

共享应用边界先接受真实合格来源，再写受体 Restrictions，后续查询不回看原源技能；同一 grant、声明序号和真实事件 occurrence 幂等。源技能仍存在时，后续真实事件可以接受新的施加；源技能消失后只保留本次已施加状态，不产生未来窗口的授权。回合或濒死中途获得/明置来源，需要在同一个共享变更边界接受当前匹配窗口，不能等延迟 skillsChanged drain。不得在 while 内调用 GetShard/HasRuntimeSkill 或用新的谓词注册表处理。

第一版 `on` 只接受上述两个 before 入口，且须含对应 after 结束边界，可附加现有 OR 结束条件。加载器拒绝尚未支持的应用时点、on.skipIssued 及特定濒死身份上的 skipIssued；公共 skillState 的其余期限组合没有收窄。现有回放仍用配置与命令前缀，没有新增玩法 epoch 或覆盖不可恢复的旧存档。

`ruleWounded` 读共享规则受伤权威，`equipmentSuitCount` 使用已经合格的独立根及允许的低层改写，`publicPileCount` 读具名公共堆的真实实体。前两项依赖技能来源，只用于效果和受静态叶校验约束的条件授予；受体持续限制的 raw while 加载器拒绝它们，避免压制改写来源又回看有效花色的自递归。公共堆是 raw 事实，可复用在两种条件中。花色统计共用有序、忽略 None 的原算法，不调用最终 EffectiveSuit/GetShard；不宣称所有上下文花色改写都已迁移。

## 规则格式版本：唯一来源与边界

测试中的当前规则版本应由 `SkillProgramCatalog.RulesSchemaVersion` 或共享夹具辅助方法生成；刻意不兼容的版本负例保留。当前格式是开发批次的门禁，不是每个动作的玩法 epoch。不兼容格式的退役按开发批次统一升级，不逐操作提升版本。

测试规则字符串统一使用 `SkillProgramTestJson.CurrentSchema`，Core/WPF 共用同一辅助方法。它只替换当前版本占位，不提前解析畸形 JSON；旧格式拒绝用的 Replace 片段也引用同一来源。原常量场景改用不依赖初始化先后的静态表达式属性，展示、checkpoint 及故意错误版本保持各自边界。

已核实：`SkillPrograms.cs` 规则根版本只用于加载入口等值校验；技能 GameplayHash 来自 RuntimeVersion 与单个 skill 的 canonical JSON，不包含根版本。`ContentRegistry` 指纹由已解析内容构成；`Replay` 保存命令、配置、包签名和 ContentHash，没有持久化规则根或 RulesSchemaVersion。展示、checkpoint 与外层 save 的格式各有独立来源，不随本方案变更。

**内置格式边界（已实施）**：随代码编译的内置规则删除根 schemaVersion，由 `EmbeddedSkillProgramCatalog` 的唯一资源加载点显式选择当前源格式；只区分根门禁，后续技能解析、未知字段/指令拒绝和指纹函数共用同一路径。对外 `SkillProgramCatalog.Load` 及 Inspect 工具仍要求显式版本，避免把“字段仍合法但含义已变”的旧外部文档默认为当前格式。已引用常量的生产 C# 规则生成路径保留原加载方式。

这是内置内容源格式变化，无须增加存档字段、RulesVersion、包版本或玩法 epoch。纯删除根字段可保持所有 GameplayHash 与 registry ContentHash；真正修改技能步骤导致的指纹变化仍照常生效。实施时应以同一整合源码对比去字段前后的全部指纹并复用冷恢复检查，不能把本批实际无前规则变化一起算成“格式迁移保持兼容”。未知字段校验能拒绝旧拼写，不能独自识别合法字段的语义变化，因此外部文档的格式标识仍有意义。

## 内置规则格式：显式选择当前格式

嵌入程序集的 `*.rules.json` 不包含根 `schemaVersion`；`EmbeddedSkillProgramCatalog` 在唯一资源加载点改用 `SkillProgramCatalog.LoadCurrent`，明确选择当前实现的源格式。这一批不修改技能步骤、玩法规则或 RuntimeVersion，也不计入外观事实需求的依赖清理；之前批次的规则修改与指纹变化不归入这次格式对比。

`LoadCurrent` 要求无版本根，出现 `schemaVersion` 会按未知字段拒绝；它不是猜测版本或兼容旧外部文件的入口。对外 `SkillProgramCatalog.Load` 保持严格版本要求，缺失、错误的规则版本仍拒绝。Inspector 内置示例与直接读取这些资源的夹具显式选用当前格式入口；用户提供的外部规则仍走严格入口。生产 C# 中已引用版本常量的规则生成代码保持原加载方式。两个入口只在规则根门禁处区别，后续技能解析、字段与操作校验、重复键拒绝、展示配对和集合冻结共用原路径。展示、checkpoint、外层存档和包版本均保持各自的既有边界，不增加玩法 epoch 或存档 RulesVersion。

删除内置规则根格式版本不改变技能程序 GameplayHash 与目录 ContentHash；技能步骤或其他内容真正改变时，指纹仍须改变。内联生成程序继续参与目录指纹，保持其原加载与版本边界。

直接读取内置资源的入口复用统一 catalog；需要改写 JSON 的夹具显式补当前规则版本后仍走严格外部入口，不增加兼容回退。

RuntimeVersion、外部规则版本、展示、checkpoint、save 与包版本均保持各自边界；内置根元数据迁移不新增 RulesVersion 或玩法 epoch。

### 归属、时点与身份

实际历史归属原生命令／结算边界：`ActualCardUseHistoryCaptureRuntime` 发行缺少的时点事实，`ProgramEventHistoryIndex` 从原 journal 增量派生只读 `IActualCardUseHistoryQueries`。索引不是 pending；真实付款、选择、RNG、游标与类型化子返回继续留在原帧。共享能力不依赖人物，也不在查询时补写记录。

|---|---|

| 身份与目标 | `useActor`、`useDeclarer` 分开回答当前使用者与首次接受者；`useTargets` 按所选视图读 designated 或原始确认目标。`usePrimaryTargets` 在确认视图读确认元数据，在 accepted／finalizations 分别读已达阶段／首次 finalized 的主要目标。`useDeclared` 区分仅接受与真实原生声明。 |

| 时序与集合组合 | `atOrBefore(use,currentUse,"accepted")` 保留接受顺序；`first`／`last`／`takeLast` 只在所选视图内取序，`sameUse` 比较真实用牌身份。`useFinalized`／`useCompleted` 读取已达阶段；`intersect` 保留左侧角色顺序。`filter`、`targets`、`contains`、`any` 和 `count` 组合事实与角色集合，fact 的 `use` 与角色的 `it` 各自有作用域。 |

`CardUseHistoryPoint` 的 Cursor 是包含待提交事件的完整 journal 长度，不是公开 Envelope.Sequence；它还冻结实际回合、回合拥有者及可选的当前 native Use／Action 身份。窗口读取沿原 point，明确的 now 读取才取现值。目标集合结果在实际开始执行时冻结到原 receipt，子窗可以产生新历史，但不能重写已支付父帧的选择菜单。

Accepted 与 Finalizations 是同一 journal 的共同视图，不另存 Pair 账本，也不改变 Latest／Observations／Confirmations 的含义。完成窗口的 `CompletionPoint` 在原 `ActualCardUseTargetsCompletedEvent` 处冻结，不在候选收集或嵌套子结算后刷新。顺序、阶段状态与交集由表达式组合，不能把“先取尾部两项，再检查完成”改成“先过滤完成项，再取两项”。

原始队伍关系使用 `sameTeam` 读取实际 TeamId，包含自己；已知角色没有队伍时为假，参与者未知时为未知，不借用 AI 敌友估计。自然表达式组合仍受加载器有限深度约束，最多 12 层，不为人物组合增加专用读取或绕开边界。

历史采集需求由表达式 AST 与真实能力声明推导，Triggered／Activated 分开；不保人物名开关，也不依赖当时是否有人有效持有某技能。普通 Use 与原有自身闪／无懈响应协议的差别可由 `useIsResponse`／`useIsSelfNativeResponse` 表达；群体响应、协助供给材料和 hosted effect 不能冒充新的实际 Use。

## 实际阶段历史与已交付摸牌

### 阶段事实：实际进入与跳过

实际进入沿用 `ActualDiscardRecoveryPhaseStartedEvent`，实际跳过由 `ActualDiscardRecoveryPhaseRuntime.RecordSkipped` 在原生跳过边界发行 `ActualPhaseSkippedEvent`。`ProgramEventHistoryIndex` 从同一 journal 派生 `IActualPhaseHistoryQueries.CountPhases`；`phaseCount` 只读实际回合、回合拥有者、阶段行动者、阶段种类、结果和指定游标，不建人物状态表或第二套阶段调度。

恢复原 phase token 不算再次进入。自然回合槽、插入阶段的原帧与指令、额外摸牌的原帧保留各自 occurrence，同一跳过边界恢复不会重复记数。额外摸牌和替代阶段仍沿各自真实生产者采样；调度请求、替代请求、跳阶段付款均不能单独充当“阶段已经跳过”的事实。source3161 的判定阶段替换实际进入 Draw，不因此制造 Judgment skipped。

entered 也不等于阶段完整结束。弃牌阶段先进入原生开始窗，再由其中技能决定跳过时，该阶段既有 entered，也有随后真实 skipped；不能让两种结果互斥，也不能从阶段结束事件反推进入次数。屯江仍要求存在 Play entered 且完全没有 Play skipped，因此先进入后跳过的 Play 不会获得奖励。

|---|---|
| OL 屯江 | 纯 JSON：本实际回合 owner 至少进入过一次 Play，且没有任何一次 Play 被跳过；确认历史中实际 Play 主要目标不含他人。符合后以 `draw` 的 `livingFactionCount` 数量摸牌，等待原生子结算。 |

| 界移动／移动朱桓平寇 | 资格与可选目标上限共同读取实际 skipped 数量，Begin 冻结求值结果；同阶段种类的不同额外 Draw 分别计入。各版选人、伤害与装备后续仍属原效果，未宣称整技能纯 JSON。 |

共享历史不以当时是否持有蒙态为采集条件，因此本回合实际跳过阶段后才获得或恢复技能，也读取此前真实事实；此前人物持有门控造成的漏记已修正。尚未真正跳过的后续 Play 不会提前触发收益，真正跳过的自身额外 Draw 也属于 Draw skipped。只获得技能不会补造一次跳过。

### 阶段捕获需求：内容声明与对局模式合成

`ActualDiscardRecoveryPhaseRuntime` 与 `ActualPhaseEndRuntime` 的 `Tracks` 统一读取本对局的 `INativeFactDemand`。能力不再通过立世、智迟等人物开关回答是否捕获；目录是否需要事实与当前人物是否持有、有效是不同问题。

不可变内容目录编译 `ProgramDependencies.RequiredFacts`，操作描述符仍区分 Triggered／Activated。被动能力声明、通用 modifier／view-as／card-policy trait、表达式读取、触发窗口和技能状态期限共同参与编译；状态期限包括效果内的 Until 与持续声明的 `State.Until`，不能漏掉后者。仅需实际阶段身份的能力声明 `ActualDiscardRecoveryPhase`；确实依赖阶段结束的能力声明 `ActualPhaseEnd`，统一依赖闭包自动补齐身份事实。

当前选中模式的 `RequiredFacts` 在 `MatchCoreCapabilityProvider` 与程序目录需求合成，生成该对局只读 mask，不修改共享 catalog。官渡原实际阶段与阶段结束开关改由模式合同声明，其余模式运行需求保留原语义；模式边界与编译后的 mask 都拒绝未知位，不静默忽略未知需求。同一目录用于不同模式时，不能互相残留捕获需求。

声明归属按真实能力判断：立世、沉略签发／阶段末移除、孔武、OL 卢氏的阶段快照，以及倾轧、泥首、伍孚、黄祖、润微的阶段末工作归对应入口。司马师初始化不再充当所有阶段末能力的代理；沉略的主动签发与触发移除分别声明。智迟自身只读回合保护状态，旧的阶段捕获门已过时，直接退役；明策真正使用阶段身份的入口已有声明，不增加一条无用被动需求。

OwnedDraw 的 producer 启用继续保留原目录需求含义。模式要求捕获阶段事实，不等于要求额外打开 DrawSkipped 观察者帧；共享实际 skip fallback 在原生跳过边界保留原时序，不把调度请求提前记为结果，也不新增观察者 pending。

### 摸牌交付：当前步骤的续接已统一

普通 awaited `draw` 在原 `NativeDrawProducerReceipt` 标记实际交付，并在 `ProgramDrawCompletedEvent` 之前写入原帧的 `ProgramInstructionDelivery`。交付包括实际零张或合法替代，获得的替代实体仍不算 DrawPile 摸牌结果；签发请求、游标已前进或尚未返回的替代选择不等于已交付。

共享续接只允许当前已交付收据排空自己的子窗；清空 `NativeDraw` 后，只有交付游标仍对应计划最后一条 Draw 时，才可在失源或死亡后完成原步骤。该权限不能执行未付的后续选择、摸牌或其他 suffix，也不授权尚未交付的请求。真实移动、实际数量、替代结果、子返回和完成继续使用原帧与既有原生协议。

这项交付协议覆盖原生 Draw producer；不等待移动、没有 native attempt 的同步快速路径继续使用原语义，不因本概念补造收据。屯江与蒙态的声明显式使用 `awaitMovementTriggers`，没有把该选择隐含为人物特判。

## 公开展示源事实与手牌驻留

`PublicCardRevealQueries` / `IPublicCardRevealQueries.Describe` 只读取原始公开展示的母帧与实体，统一普通展示、程序展示、火攻及手牌比较的真实源事件。清靓与公开手牌分配在原生产时点直接发已有 `ProgramCardsRevealedEvent`，不再用专属事件再回查人物帧证明实体。原公开绑定、分配名单与阶段状态继续由实际生产者拥有；没有新建规范化事件流、人物事件适配器表或第二份展示账本。

狷狭火攻已在真实展示点发普通展示事件，后来发出的用牌结果不是第二次展示。共同读取不把私看、拼点、普通用牌或移牌记录当作公开展示；源事件可能同时展示牌堆、装备或真实手牌，所以读取实体不等于认定它当时属于手牌。规则仍在各自观察时点查询实际区域、持有者与有效牌面，不能从事件的原始牌面推断当前有效花色。

`CurrentHandEntryQueries` / `ICurrentHandEntryQueries` 只读原物理移牌 journal。当前不在指定角色手牌则未知，最近一次真正进入该手牌的移动序号标识这次驻留；同区域移动不换驻留，未有移动的初始手牌使用原有零值。离手后再次进入是新驻留，即使物理实体相同。蔡瑁、刘巴、孟达、王观、雅丹及罗宪使用同一读取，不再借罗宪人物实现回答物理事实。

各规则保留自己的采样与记忆范围：罗宪在 BeforeEvent 记 owner／实体／本次驻留；谬焰记实际阶段／实体；鼓曲记实际回合／来源／实体；蝶偶记实际回合／实体；绝颜在 AfterEvent 判断当时有效花色并占用轮次额度。不能用罗宪去重过的驻留记录替代所有展示 occurrence，也不能因为两次展示同一实体就合并不同轮次或来源的规则机会。

罗宪原来遗漏清靓和公开手牌分配的实际展示；源统一后，这两种展示同样参与“展示过的手牌”判断。谬焰对善刀置顶、诏颂交牌材料展示的两处排除保持原义，仍留在其规则层，没有伪装成共同展示规则。如何统一显式展示与移牌披露需要单独收口，不能简单把所有待移动材料一律排除，否则会改变其他既有消费者。

## 签发机会与触发次数：原帧预留

`ProgramTriggerUsageRuntime` 统一普通触发次数及原生用牌窗口的 Event 次数读取、消费和签发预留。存储仍是原 `SkillRuntimeStateStore` 或原 `ProgramCardTriggerWindowFrame.EventUsages`；`ProgramTriggerUsageRules` 是次数键与动态上限的唯一算法，原生查询转用同一 owner，没有第二张次数表。具名组不包含技能实例，普通绑定仍保留原实例维度，Event 次数继续属于原用牌窗口及其真实上下文。

`invocation.source: publicHandReveal` 在原公开展示的 AfterEvent 资格阶段工作。`PublicHandRevealSourceRuntime` 按角色、原手牌顺序、合格声明候选读取实际有效花色，复用同一 `CanRun` 的来源资格与条件实现；既有 `suits` 决定哪些真实花色匹配，不新增人物表达式或操作。来源资格成立后，先消费同一个次数键，再把候选和预留标记附在原展示帧，最后发布既有次数事实。窗口开始时不重新判定来源或资格，`UsageReserved` 仅避免本次调用再次消费已经支付的次数。

声明要求 owner、非可选触发，不包含 marker 付款或延后到结算时才判断的资格。本签发能力不支持 Event scope 的预留，因为 Event 次数需要真实原生用牌窗口；正常 Event 触发保留原协议。未限制次数的声明不制造一次付款，普通手工签发及其他既有调用授权默认也没有预留标记。来源失效、owner 死亡政策与次数是独立维度，不能从其中一个推导另一个。

每名角色在同一次展示捕获一份资格事实，留在原展示帧与子窗口的私有按候选序号集合，后续 `WindowContext.Facts` 使用同一时点的值。实际摸牌或嵌套展示不会改写它，公共 claim 返回事件不携带这份私密事实。原帧消费游标、类型化子返回及当前窗口授权继续约束调用，不扫描次数事件重做付款证明。

绝颜用四条普通花色声明，各自使用 Round、一次上限及固定具名次数组。原“同一 owner／轮次／花色”额度不随失去或重新获得技能重置，不随实例替换增发；真实轮次边界才清空。Round 触发直接编译 `ActualRound` 需求。留牌使用、闪／无懈／求桃响应及受邀出杀改从真实 `retained-hand-use` activation 枚举有效实例，不再借奖励 trigger 作为持有来源；已冻结的原帧 source、native origin 及邀请母帧身份不变。

## 公开展示历史：共同采样与各自记忆范围

`PublicCardRevealHistoryCaptureRuntime` 在原公开展示的 BeforeEvent 边界补捕获真实 Hand 持有者、该次物理驻留、移牌截止点及实际回合／阶段；`IPublicCardRevealHistoryQueries` 从既有 typed journal 读取同一不可变样本视图。原始展示事件只提供公开实体及来源帧，缺少这些历史位置与时点；物理移牌事件也可能不公开输出，不能在后来按当前持有者或仅按事件序列反推。本采样只补缺失事实，不复制牌面快照、不为各技能重记一份账本，也不是新的活动状态或结算状态机。

## 展示集合、绑定驻留与已接受的回合后调用

`publicRevealCards` 从共同展示历史按 all／actualTurn／actualPhase 与 all／explicit 目的筛选，之后按实体选最后一份匹配样本；`ProgramPublicRevealCards` 是表达式及低讴、谬焰原生消费者的共同投影。谬焰继续传原用牌发票的阶段，不能刷新为后来阶段。`ProgramExpressionCardFact` 只携带已知事实；展示集合只有公开身份、原 Hand 位置与驻留，不根据实体后来进入的私区补牌名、花色或获得资格。原获得快照适配为同一表达式值时保留原冻结牌面，未知驻留仍未知。

`boundCards` 读取原绑定的实体与来源见证。`cardStillAtSource` 比较原来源位置及原物理驻留；只有位置相同不足以证明没有离开后重入。`ICardZoneEntryQueries` 与原 Hand 专用读取共享物理 journal owner，同区域 no-op 不换驻留。程序声明需要此读取时，原材料生产者在子结算前冻结对齐的 `SourceEntrySequences`；普通过滤、子集和表达式捕获继承原见证，不把未知 token 或离开后回归变成新的原点。新物理移动结果仍以其真正交付为新的结果来源，不混入原消费材料。

AfterTurnEnded 的 `invocation.source: afterTurnEnded` 在真正接受、原费用及父 CurrentChild 已接通后才写已有 `ProgramInvocationAuthorization`；曝光提示、候选采集和旧来源资格本身不签发权限。授权约束原父、当前 item、候选、事实及实际子帧，来源消失后保留本次已接受调用，不转化为持有技能或未来发动权。死亡缺省 stop，已付翻面或 Draw 的子窗由执行器排空，不能据此发行尚未支付的 Draw 或展示后缀；完成与取消均经原类型化父返回清除授权和推进游标。

带砺使用普通 anyLiving 实际回合结束声明，保留回合主人已死亡时仍可发动的原义。资格是当前本人手牌中仍属已展示驻留的去重数为偶数，零也成立；接受后依次翻面、普通 awaited Draw3、过滤原摸牌驻留、非空时公开展示。原摸牌实体离手后即使返回也不展示，后来另摸的实体不混入。Draw 只绑定真正 DrawPile 交付，合法替代获得不是摸牌结果；该配方接入已有原生摸牌请求及替代能力，旧专用直接 Draw 路径不再旁路共同能力。带砺的专属操作、加载器契约、Runtime、私有付款事件、保留钩子、续接及回合后白名单退役。

普通 `revealBoundCards` 可用既有 expression 条件决定是否执行，带砺以 boundCount 排除空展示；该条件不制造新操作或改变其他消费者的显示协议。AI 只消费其已知来源，未知结果、私密位置或原点保持 unknown，不把历史公开身份当作后来私牌的读取权限。

回合后其他调用尚未全部声明化。蟨蛮的结束摸牌子支可复用接受授权，但同一原生操作另有强制用牌分支；直节在未选目标时不保留，典军还含额外出牌阶段及返回清理，立文只在分配付款后保留且死亡后仍可排既定他人用牌队列，现营则是此前签发、可在本次 Begin 前失源的跨窗口承诺。它们不能一律替换为 Begin 后 sourceLoss retain／ownerDeath stop。
