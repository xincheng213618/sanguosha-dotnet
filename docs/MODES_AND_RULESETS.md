# 模式、选将与发牌

模式由 `ContentModeDefinition` 注册，使用 `ModeKind`、身份／队伍／势力人数、武将池、候选配置和牌堆 ID 描述。Core 复用同一命令、结算与牌区移动系统；WPF 的默认大厅入口由 `MainViewModel.TableModes` 提供。

## 运行时模块边界

场次模块使用同一个 `GameEngine` 命令事务、确定性随机源和结算栈，不创建独立牌局或第二套事件总线。当前依赖关系为：

- `CardGame.Core` 定义场次接口、受控宿主、不可变计划，以及应用计划和推进原生结算的操作。
- `CardGame.Modes.Standard` 仅依赖 Core，负责现有场次的配置校验、默认场次、规则配置、装备配方、展示与势力策略，以及座次、选将、牌堆和初始装备计划。
- `CardGame.Modes.Activities` 仅依赖 Core，负责虎牢、驱鬼、十殿、年兽的流程，以及山河、剑阁、神武、文和、官渡、龙舟的场次规则、轮次推进、奖励与胜负边界。
- `CardGame.Modes.Wushuang` 仅依赖 Core，负责无双的命令、商店经济、战法、计时、回合间歇和局内成长。
- `CardGame.Content.Standard` 显式注册这些工厂；Core 不扫描或加载具体模块程序集。

`IMatchModeSetupFeature` 返回冻结的开局、候选、选将和装备计划。Core 将它们应用到原有角色、私有候选字段、牌区和技能授予中；候选不会另存一份挂起状态。模块通过 `IModeSetupRandom` 使用本局随机源，保留原调用顺序；`ProjectDeckCardNames` 只投影牌名，不抽取虎牢装备或消耗随机数。

默认开局和规则配置分别由通配 `StandardModeSetupFactory`、`StandardModeProfileFactory` 提供。独立场次可以按 `ModeId` 注册 `IGameModeSetupFeatureFactory` 或 `IGameModeProfileFeatureFactory`，分别覆盖这两个入口；只替换选将不会丢失原有规则、展示和装备配方。相同入口的同目标工厂会报冲突，其他观察器和流程工厂继续加载。复制注册表时使用 `CopyModeFeatureFactoriesFrom` 保留显式绑定；包装 `IContentRegistryBuilder` 的适配器须透传模块、装备注册及工厂存在查询。

外部规则通过 `IMatchModeRuleObserverProvider` 和 `IMatchModeRuntimeHookProvider` 插入现有阶段及优先级。命令、开局、结束边界、数值与距离查询、初始发牌、快照投影、原生结算帧和询问答案均使用公开接口进入同一命令会话。伤害规则按原有优先级与原生规则合并；重复优先级和重复入口在建局时拒绝。模块只取得白名单内的受控宿主和冻结事实，按需调用原生操作；构造模块无需读取已开局状态。

规则配置声明本场必须安装的功能接口，缺失或重复会在建局阶段报错。装备由本局配方创建，无双商店、战法和活动装备只随对应模块及配方启用。共享执行链只执行已安装的接口，不按活动 ID 选择实现。

`ModeRuntimeRequirements` 声明场次对实际阶段、原生摸牌、轮次结束、目标定稿及伤害基数记录的需求；Core 再合并内容依赖和当前技能的需求。牌规则选择重铸槽位、原生牌身份和额外基本牌转换族，付款、动作顺序与实体校验仍沿用原执行器。神武的座位与版本阶级、地府的阶级特权、剑阁的友军伤害上限由对应活动模块解释。

`IMatchModeAllegiancePolicy` 解释本场的公开势力、身份死亡取样、主公投影许可和队伍关系，支持独立替换规则配置。传入策略的是标量事实；暗置主副将的选择与明置证明、精确技能来源和结算帧身份继续由 Core 校验。国战的暗置信息不会作为公开势力传给外部模块。

护甲授予许可由规则配置决定；无双的禁止增甲仍在原生指令和目标校验完成后执行。文和模块决定毒牌离区资格与体力损失数值，Core 持有原始移动批次、实体和顺序，继续验证并推进一次性付款、体力变化及濒死子结算，不新增独立的毒牌挂起状态。

虎牢的同步 `ModeFlowInterruption` 只在当前命令内交还流程控制：已支付牌保持支付，原生栈和处理区由 Core 清理，仍记录原有取消、回合结束和关卡事件。血线变身后先锋先手，首次洗牌变身后 Boss 先手。驱鬼和十殿的连续关卡等待击杀动作和死亡子结算全部结束，再替换 Boss 并保留联军及当前回合。文和和官渡的全局阶段推进由模块决定；原生帧仍验证付款、来源、父子返回和所有者。活动牌及武将技能的实体移动、濒死、响应、合法目标和恢复证明继续复用 Core 的原生机制。

上述绑定属于运行实现，不新增存档字段或规则版本。玩家快照、事件冻结、牌区移动、命令校验与存档重放继续由 Core 统一处理。

## 身份与选将

身份局主公公开，其他身份仅本人可见，死亡后公开。主公固定为 1 号位并首先选将公开，本地玩家接着选，其余 AI 随后选择。选将完毕时其余武将公开，首回合由主公行动。

经典身份模式按角色配置候选数量：主公、内奸各 13 个，忠臣、反贼各 8 个。按人物等概率、不放回抽取候选，再等概率确定实际抽中的版本；强度评分不改变抽取机会。候选生成后固定，进入自选名录再返回不刷新。玩家可预览配置允许的同人物版本；AI 也可互换普通版本，但谋、神、魔、友系列只有实际抽中时才进入 AI 的候选。确认出征才提交最终武将 ID，同人物其他版本随后退出本局将池。完整武将名录仍受模式池、同人物冲突和已选武将约束。私有候选只对所属玩家可见。具体策略见[选将说明](content/IDENTITY_DRAFT.md)。

选定神势力武将后，身份开局通过 `SelectFaction` 询问选择本局有效势力；本人从魏、蜀、吴、群中选择，AI 使用稳定选择。运行时有效势力用于护驾、激将、救援等查询，内容定义中的武将势力仍保留原值。

经典身份以武将基础体力初始化，主公上限加 1；有独立初始体力的武将使用其定义。初始手牌按牌堆配置发放，玩家确认起手牌后开始对局；确认前可将自己的起手牌放回并重新洗抽，其他角色手牌不变。

## 身份胜负与死亡奖惩

八人双将模式中，每席连续选择主将、副将，允许跨势力搭配。两将共用一个角色、手牌、回合及装备区，两将技能同时生效，主公技继续受身份限制。体力上限为两将基础体力之和除以 2 后向下取整，主公额外加 1，开局满体力；势力和性别沿用主将，神主将仍按现有流程选择有效势力。候选数量、同人物版本冲突、主公先公开、其他角色开局亮将、牌堆、死亡奖惩与身份胜负规则均沿用八人经典身份。

- 主公、忠臣：主公存活，反贼与内奸全部死亡时共同获胜。
- 反贼：主公死亡，且不满足内奸唯一存活条件时获胜。
- 内奸：主公死亡时自己为唯一存活角色才获胜。
- 击败反贼的存活伤害来源摸 3 张牌，不限自身身份；主公击败忠臣则弃置全部手牌和装备。

## 2v2 阵营

青队与赤队公开，座次按双方交错排列。玩家可选择所属队伍，队友手牌仍隐藏。模式使用单将与私有候选，武将结果在选将结束后公开；首行动队伍由确定性开局流程选择，先手首个摸牌阶段少摸 1 张。

对方两名成员全部死亡时获胜。死亡牌按通用清理流程进入弃牌堆，不使用身份局的击杀奖惩。AI 的敌我关系来自公开 `TeamId`。这是项目的简化队伍规则，详见 [`TEAM_EXPERIENCE.md`](TEAM_EXPERIENCE.md)。

## 剑阁决战

剑阁活动场采用用户确认的旧版截图规则，玩家固定五阶；难度控制英灵和器械等阶，万夫莫开只加成普通武将席位。完整加成、首批 NPC 与本地范围见[剑阁活动规则](JIANGE_ACTIVITY.md)。

## 驱鬼逐邪

活动场的驱鬼逐邪采用 OL 2018 四关版，四关分别从魑魅魍魉、牛头马面、黑白无常、罗刹夜叉中抽取一名 Boss。玩家沿用已选定的五阶本地规则，默认两名人机队友。新关卡在原击杀动作及全部死亡技能结束后登场，当前回合继续，联军状态保留；末关死亡技能仍可能使联军失败。版本来源与本地补充见[驱鬼规则](GHOST_ACTIVITY.md)。

## 虎牢关

活动场的虎牢关采用 OL 2022 合作版，五阶玩家与两名人机搭档挑战神吕布。最强神话体力降至4或首次洗牌时中断当前回合，随机变为暴怒战神或神鬼无前；第二次洗牌后的当前回合结束时联合军失败。包含真实武器重铸、联军盛宴、四种专属装备、联军阵亡补偿及存档恢复。普通锦囊转换及静态锦囊触发通过本局规则支持活动牌，将池按官方禁将筛选。版本冲突、变身保留状态和新增牌面约定见[虎牢关规则](HULAO_ACTIVITY.md)。

## 神武再世

神武再世采用 OL 2017 单关版：三名联军按顺序从各自五名普通候选和三名共享神将中选将，对抗四种首领之一及两名烛阴。首领首次半血永久获得指定技能；首领死亡即可获胜，死亡子结算仍须完成。包含军争替换牌堆、撒豆成兵、移花接木、八神专属装备与联军补给。玩家默认五阶，两名人机搭档；服务端计时、商城与付费复活不模拟。具体官方来源、本地补充及复用神将版本见[神武规则](SHENWU_ACTIVITY.md)。其他已研究的活动见[活动场清单](ACTIVITY_MODES.md)。

## 挑战年兽

采用用户选定的OL 2016三对一版本：初始12体力，第二轮起在睿智、警觉、任性、暴怒中逐轮随机换态，同组四种不重复。玩家默认五阶、两名人机搭档，全队共享三次协力复活；保留30分钟实际时限和可重放的时间消耗，离线时间不补计。官方禁将、技能原文及本地补充见[年兽规则](NIAN_ACTIVITY.md)。不混入2020随从和觉醒、2022生肖捕捉规则。

## 十殿阎罗

采用 OL 2020 2.0 四关版，前三殿随机一殿登场孟婆，50实际回合内通过第三殿且真正击杀过孟婆时，地藏王替代末殿转轮王。玩家固定五阶，使用该活动官方的起手增加2与一次重生规则；敌方一至五阶独立可选。包含十二名敌方角色、真实技能遗失与实体回魂、判定指定、坐骑重铸及跨关恢复。版本来源和公告未明确处的本地约定见[十殿规则](HELL_ACTIVITY.md)。

## 龙舟争渡

采用OL 2018双端八人四队版：只用本队势力的六名候选，队友互见候选；对敌造成的实际伤害为全船增加至宝，上限12。两个实际轮次结束后按分数与到达先后排名，额外回合不推进轮次。包含艾叶濒死保护、粽与雄黄酒、三张活动锦囊及四名活动专将；玩家固定五阶。官方来源、专将分配和同分处理约定见[龙舟规则](DRAGON_BOAT_ACTIVITY.md)。

## 国战 M3

每席按系统分配势力选择两名不同的同势力武将，主将、副将分别暗置。基础体力取双将平均并向下取整，开局满体力。自己的出牌阶段或杀响应询问中可独立明置槽位，明置后对应完整技能列表才生效，势力随首次明置公开。未明置的另一槽位继续隐藏。

魏、蜀、野心家按 3／2／1 分配；`SoloFactionIds` 校验野心家独立势力只有一个席位。最后仍有存活成员的势力获胜。该模式是人数与独立势力试验，没有完整野心家转换判定、珠联璧合、阵法、围攻、变更副将和完整国战专属牌堆。详见 [`NATIONAL_WAR_EXPERIENCE.md`](NATIONAL_WAR_EXPERIENCE.md)。

## 牌堆与恢复

`ContentDeckRecipe` 可以使用逐张 `PhysicalCards` 配方表达定义 ID、花色和点数，或者使用数量配方；注册表要求两种配方恰好选择一种。经典身份提供标准与军争逐张牌堆，其他模式使用自己声明的牌堆。

洗牌由确定性随机源执行，起手发牌逐轮按座次进行。实体牌移动进入统一账本，玩家只看到自己的牌面与他人的公开数量。存档保存开局参数、内容包签名、内容指纹及已接受命令，恢复按当前实现重放并验证，详见 [`SAVE_AND_RESUME.md`](SAVE_AND_RESUME.md)。
