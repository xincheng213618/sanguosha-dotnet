# AI 阵营决策与可见信息

`SimpleAiBrain` 是确定性启发式 AI，从本座玩家快照、Core 发布的合法行动／私有询问和公开行动证据中选择操作。当前策略包含动态实体牌估值和有界的一步战术规划；它不读取其他角色暗牌、隐藏身份、牌堆顺序或宿主结算栈，没有通用游戏树搜索、跨局学习或难度分档。

## 决策范围

- 身份局结合自己的身份、公开主公／阵亡身份和公开攻击证据判断敌我；2v2 使用公开 `TeamId`；国战使用自己的势力、已公开势力及受约束的暗势力置信度。
- 群伤比较双方公开体力、手牌数量与敌我净收益；需要保护主公时避免在主公仅剩 1 血时主动群伤。桃园结义只计算受伤角色的阵营回复收益。
- 饮酒要求存在另一张能合法使用且有正收益的杀，低血量时考虑保留酒自救；同一实体牌不会同时用作饮酒与转化杀。
- 普通与转化用牌比较实体费用的保留价值；距离、次数、目标禁止和当前可用转换都来自 Core 合法动作。
- 狩骊的外场实体费用按已发布的转换来源，从玩家视图中公开的装备／判定区读取；直接杀和饮酒后续估值共用该查找，不将他人的手牌作为材料来源。
- 无懈区分有益、有害效果及反无懈方向，救援与辅助选择复用阵营判断。移除判定区限制牌按帮助其拥有者计分。
- 配置技能使用公开 AI 摘要、本人可见费用和已发布候选评分；观星、改判等私有选择只消费询问提供给拥有者的资料。
- 国战明置比较主副将技能与自己当前手牌、体力、公开目标机会；已公开势力优先于置信度，暗势力证据限制在 [-6, 6]。
- 重铸和重复主动技能有本回合的 AI 进展保护，避免循环；这些保护不改变玩家的合法动作。

## 动态牌价与一步规划

`AiDecisionPolicy.TacticalPlanningVersion` 起，主动技能费用与选牌共用动态保留价值。唯一自救酒、最后的闪，以及由本人已发布转化能力支持的响应材料会提高机会成本；多余响应牌与超出手牌上限的普通杀按实际用途估值。技能摘要仅用于估计保留价值，不表示未来响应一定合法，实际支付仍服从 Core 发布的牌数、花色、费用与目标关联约束。

原生决斗还会比较支付后剩余的杀响应材料、自己的体力与护甲、对方公开手牌数和已公开转化能力。对手杀数量使用明确的启发式先验估计，最多处理三十二张公开手牌数量，不读取暗牌；已用作决斗费用的实体不能同时算作响应材料。低生存余量会提高预计失败代价，避免没有响应储备仍贸然决斗；牌多不表示对方一定有杀。

当前一步规划只比较已经发布的动作：移除敌方公开防具后，是否还能以另一张独立的手牌对同一目标使用已有的合法杀。每个准备动作最多比较十二个相容攻击，折扣预计续招收益，不创建未来合法动作或持久计划。拆白银狮子的回复代价、保留藤甲火焰弱点以及已有无视防具效果会影响顺序。每次实际结算后重新选择，移动触发、无懈或其他技能仍可能令原续招失效。

Core 在普通实体杀的合法动作上附带不可变的 `PublicSlashTraits`，表达本次预计颜色、属性和防具绕过情况。AI 不把实体牌印刷花色当成本次用牌颜色：例如吴景的首张实体杀可以改为方块。该摘要仅提供给行动拥有者，不能作为命令输入或绕过规则校验。技能改变后续结算时，以实际结算为准。

普通杀、准备动作和饮酒的后续杀使用相同的新策略修正，避免先饮酒再发现唯一的杀会被防具阻挡。旧策略保留原评分和随机调用路径，当前策略的新增估值也不把已经拒绝的负收益动作重新提升为可用行动。

设计参考了 [QSanguosha 的保留价值和动态使用优先级](https://github.com/Mogara/QSanguosha/blob/master/extension-doc/12-SmartAI.lua)及 [noname 的技能收益与效果修正](https://github.com/libnoname/noname/blob/main/docs/lib-skill-format.md)。实现使用本项目的快照、合法动作和原生规则查询；当前没有接入 Lua／JavaScript 引擎或训练模型。

## 身份局目标与推断

`AiDecisionPolicy.IdentityStrategyVersion` 起，身份局使用模式定义公布的主公、忠臣、反贼、内奸人数，扣除本人及已经公开的身份，对其余座位进行人数约束的联合概率推断。快照只增加不可变的公开身份配额，不增加隐藏座位与身份的对应关系。定向攻击主公是较强的反贼线索；群伤的被动受击名单不作为定向敌意。公开行动证据有界并逐步衰减，矛盾行动能够纠正早期判断，阵亡公开身份也可修正此前攻击的含义。行为证据保留不确定性，只有公开人数与身份足以确定时才得到确定角色。

反贼优先对主公形成有效压力；主忠优先压制正在威胁主公的角色，主公考虑误杀忠臣的弃牌代价。危险体力的主公提高回复优先级，忠臣在自身仍能存活时保留最后一张实体桃救助一血主公。内奸根据公开体力、护甲、装备、手牌数量与身份概率估计阵营实力，保护尚未进入单挑的主公；主忠明显占优且最后反贼线索很强时，可暂缓致命攻击，进入两人残局后转为争取单挑胜利。这些估计仍可能误判，不读取对手暗牌或隐藏身份。

反贼对低置信的未知目标保留适度施压权重，主公无法攻击时仍可处理身边的阻力；人数先验本身不会把一半概率同阵营的未知角色全部划为强盟友。已有明确公开身份或较强同伴证据时，继续避免攻击和削弱同伴。攻击、救援与无懈在高置信的最后反贼保护场面共用控场条件。

身份目标在普通战术评分之后计算，不将已经拒绝的攻击重新变为正收益；反贼对可用主公攻击的查询只在一次决策内缓存。非身份模式继续使用原有团队／势力判断，旧策略保留原观察与评分路径。

`AiDecisionPolicy.RebelStrategyVersion` 起，反贼的目标评分使用当前合法动作的公开伤害预测，区分主公实际损血、仅消耗护甲和完全无效的攻击；主公手牌数量只作为杀的命中先验，不视为已知有闪。已有有效攻主动作时减少侧路分散；没有有效攻主动作时，结合公开薄弱点和阵营概率处理阻力。拆防仍复用已有的一步规划，要求后续杀有另一张独立的实体费用，每次结算后重新判断。

群伤若可能使高置信同伴濒死且不能同时终结主公，会降低出牌意愿；可能终结主公时提高阵营胜利的优先级。反贼自己仅剩一血和最后一张桃时，对身份仍不确定的救援更谨慎；对高置信一血同伴的有害锦囊提高无懈保护意愿。命中、濒死和终结都只是当前公开条件下的估计，实际响应、救援与技能结算仍由规则决定。新评分替换上一策略的反贼目标修正，不叠加同一份攻主奖励；其他身份继续使用原有目标评分。

`AiDecisionPolicy.RebelPressureVersion` 保留原身份策略已经计价的攻主、费用和响应风险，只按主公公开手牌数量折扣新增的攻主奖励，避免把整段基础评分一起压低。不能有效攻主时继续集中公开侧路薄弱点；已有攻主机会时仍保留结束侧路战斗的价值。群伤的额外保友限制针对公开空手的一血高置信同伴，手中仍可能响应的同伴继续参与原有群伤净收益估计。前一版本的评分仍按保存的策略号保留。

默认的 `AiDecisionPolicy.RebelCoordinationVersion` 使用第七版的身份目标、救援和无懈评分，仅收紧单目标杀、决斗、火攻的盲打：目标身份未公开、联合推断的反贼概率较高且高于忠臣概率，又没有足够定向攻击线索时，暂缓投入伤害牌。公开主公及有明确敌对证据的目标继续按原评分处理，不改变模式的敌我关系、合法动作或技能规则。该限制也可能使远离主公的反贼暂时持牌，因此对打需同时观察胜率、同伴误杀、攻主伤害和局长，不能只以少出牌或少误伤认定变强。第八、九版独立保留其历史行为，默认策略不叠加其攻主奖励与额外救援修正。

## 费用与目标组合

主动技能可通过 `SelectableCardTargets` 发布费用牌与目标的对应关系，通过 `SelectableTargetSequences` 发布完整有序目标组合。当前策略在选费用、选目标和计算收益时使用同一组约束，防止从各自合法的单项拼出不合法组合。

WPF 新局显式使用 `AiDecisionPolicy.CurrentVersion`，常量与支持范围定义在 `src/CardGame.Core/Replay.cs`。`GameOptions.AiPolicyVersion` 与每局参数一起保存，受支持范围由 `AiDecisionPolicy.IsSupported` 决定，恢复时保留记录的策略版本。

AI 策略版本是回放行为的一部分，评分与随机调用顺序不能随意改变已发布策略。它独立于内容指纹，恢复按当前实现校验存档结构、内容与命令。

## 公开证据与建议器

`PublicAttackEvidence` 表达杀、决斗、群体攻击与火攻的公开来源和目标证据。身份局及国战只根据已公开关系更新各自观察状态；观察记录属于每个 AI 实例，不作为对其他玩家隐藏资料的读取入口。

玩家出牌建议使用另一个固定种子的 AI 实例，采用当前策略版本，只处理普通玩家快照与当前合法动作，不改变实际对局 AI、随机状态或命令历史。建议没有积累历史攻击观察，因此仍需玩家自行判断未明身份。详见 [`PLAY_ADVICE.md`](PLAY_ADVICE.md)。

确定性只保证相同输入和策略产生可重现选择，不能保证最优行动或阵营判断正确。回放、内容指纹和保存失败行为见 [`SAVE_AND_RESUME.md`](SAVE_AND_RESUME.md)。

## 新旧策略对打

Core 检查程序集的 `--ai-duel <output.json> [pairs] [baseline-policy] [candidate-policy] [first-pair]` 运行显式的配对诊断，不进入默认 smoke 或 routine。默认比较前一策略和当前策略，以固定种子、相同初始武将和手牌交换新旧策略所属阵营；起始组号用于复现失败组或选择另一段固定种子。测试工具仅在内部替换 AI 实例；双方使用相同宿主策略，实际决策继续接收各自玩家快照。

2v2 的混合策略对抗是主要比较；身份局按主忠、反贼、内奸分别报告，不能合并为一个同等条件的胜率。每局还检查完成状态、结算栈、处理区和实体牌库存。平衡比较使用两局均成功的完整配对，失败局和其成功的另一局仍保留在原始证据中。配对的两局相关，小样本和标准武将池结果不代表全部武将强度；全新 AI 自我对弈能够完成也不是胜率提升的证据。临时对局 JSON 和日志放在忽略的 `.artifacts/benchmarks/`，不进入源清单。

身份局专项使用 `--ai-identity <output.json> [seeds] [baseline-policy] [candidate-policy] [first-seed] [standard|active|classic]`。每个固定种子分别运行五人与八人局：一场全基线对照，再各运行一场只升级主忠、只升级反贼和只升级内奸的实验。相同开局由完整快照哈希、逐座武将与初始手牌核对，其余阵营及宿主自动选择保持基线；因此比较的是对应阵营决策器升级的影响。候选与基线版本相同可运行 A/A，要求终局和决策哈希完全一致。

命令末尾还可附加 `[5|8|all] [all|control|LordAndLoyalists|Rebels|Renegade]`，只重现指定人数或升级指定阵营；指定一个阵营时仍运行配对的全基线对照。评测为每个输出建立独立、不可覆盖的逐行 journal，及时保存开局、完整结果和有界进度／故障诊断。进度取自可信本地诊断，不进入 AI 输入；进程中断后的未完成槽不能作为完成局或平局。扩大验证应先固定评分，再在未参与调参的种子区间比较。

专项结果按人数和阵营报告胜率、改善／退化配对以及配对差值区间，并保留失败、库存与结算审计。三个阵营共用一次基线对照，结果互有关联，不能合并为总胜率。不同 profile 使用各自注册的牌堆与武将池，扩展验证需另选种子区间；普通、主动技能与经典池结果不能互相替代。混合策略注入只存在于检查工具中，不是可回放存档，正常新策略完整回放由版本回归检查验证。
